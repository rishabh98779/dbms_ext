Part 4 — Essential SQL Reference

A compact, copy-ready reference. Side-by-side differences are marked. All MySQL syntax is 8.0; Oracle is 12c+ unless a version note says otherwise.

Compatibility flags used throughout

MySQL: enforced CHECK needs 8.0.16+ · EXPLAIN ANALYZE 8.0.18+ · EXPLAIN FORMAT=TREE 8.0.16+ · FOR UPDATE NOWAIT / SKIP LOCKED 8.0.1+ · performance_schema.data_locks 8.0.1+.
Oracle: identity columns and FETCH FIRST need 12c+.

-- Canonical transfer (reset script first: UPDATE u3_account …; COMMIT;)
-- MySQL
START TRANSACTION;
UPDATE u3_account SET balance = balance - 2000 WHERE acc_no = 101;
UPDATE u3_account SET balance = balance + 2000 WHERE acc_no = 102;
COMMIT;

-- Oracle: the same without START TRANSACTION (a transaction starts at the first DML)
UPDATE u3_account SET balance = balance - 2000 WHERE acc_no = 101;
UPDATE u3_account SET balance = balance + 2000 WHERE acc_no = 102;
COMMIT;
Two rules that decide most transaction exercises
  • DDL commits implicitly in both databases — a later ROLLBACK undoes nothing (U3-D-02).
  • A failed statement rolls back only itself; the transaction stays open, so an explicit ROLLBACK/COMMIT is still required (U3-B-04, U3-C-23, U3-D-01).

-- MySQL: read a row exclusively, so a second session blocks (the classic lost-update fix)
START TRANSACTION;
SELECT balance FROM u3_account WHERE acc_no = 101 FOR UPDATE;
UPDATE u3_account SET balance = balance - 1000 WHERE acc_no = 101;
COMMIT;

-- MySQL: book the first free seat without racing another session
SELECT seat_no FROM u3_seat WHERE train_no=12001 AND status='FREE'
  ORDER BY seat_no LIMIT 1 FOR UPDATE SKIP LOCKED;
Oracle restriction worth memorising

Oracle does not allow a row-limiting clause (FETCH FIRST) together with FOR UPDATE. Use a per-row FOR UPDATE NOWAIT loop instead (U3-B-08).

-- Transaction failure recovery, MySQL (the only "recovery" both engines expose to SQL)
START TRANSACTION;
SAVEPOINT sp_104;
INSERT INTO u3_fee_log VALUES (104, 900);
UPDATE u3_account SET balance = balance - 900 WHERE acc_no = 104;
-- ERROR 3819: Check constraint 'chk_bal' is violated.
ROLLBACK TO SAVEPOINT sp_104;      -- undo this posting only
COMMIT;                            -- keep the earlier postings
What SQL cannot do

Neither engine exposes deferred modification, shadow paging, a manual UNDO/REDO pass or a 2PL/TO/OCC scheduler switch. Those exercises (C-11 to C-17, C-21, C-22, C-24 to C-29, D-05 to D-22, D-24 to D-27) are paper simulations — the SQL half only shows the effects of the recovery machinery.
